# Known Device Farm failures: a gating pass failing *only* these checks on
# this phone is reported, loudly, and does not fail the run. Anything else —
# another check, another phone, a crash, a wrong rasterizer — still does.
#
# Why this file exists. The alternatives were worse: lowering a budget (a
# 30 fps target for cheap phones) would define the problem away for exactly
# the people who own them, and making a phone observe-only would hide it.
# Here every exception names its phone, its pass, its checks and the reason,
# and `run-android.sh` says when one stops failing so it can be deleted —
# an entry is a debt with a label, not a mute button.
#
# Format, one per line, `|`-separated:
#   model (ro.product.model) | pass (cpu, gpu, auto, or *) | checks (space-separated) | reason
#
# The model, not Device Farm's name for the phone: on the test host
# `DEVICEFARM_DEVICE_NAME` is the phone's own hostname (`LMQ72034176a83` for
# the Stylo 5), which matched nothing — so the first run with this file
# (39417211158) failed the run on exactly the checks listed here. The model
# is the `model=` line of the phone's result.txt.
#
# Gating passes (run-android.sh): `auto` (what ships), `cpu` (the fallback;
# judged at the rate the app adapted to — 60 Hz on a 120 Hz panel it cannot
# hold), and `gpu` where `auto` chose the GPU.
